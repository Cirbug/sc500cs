# A 板对焦失效现场诊断（2026-11-01）

## 本轮操作

- 只读采集 COM9、COM16，各约 22 秒，115200 8N1；打开前设 DTR/RTS 为低，没有发送命令。
- 没有修改 FPGA/MCU 源码，没有连接 debug 写寄存器，没有 RAM 或 Flash 下载。
- A 当前仓库 HEAD 为 `6aedaa4`，本次采集前工作区干净。

## 现场证据

A 板 COM9 在 17:26:26 至 17:26:47 持续报告：

```text
VCM: s=6 p=0 fault=3 nack=0 phase=5 b=1000D req=5 af=8
```

按当前 `lens_i2c_ctrl.v`、`lens_serial_diag.h`、`autofocus_control.h` 解码：

| 字段 | 含义 |
|---|---|
| s=6 | busy=0，init_done=1，error=1，控制器错误已锁存 |
| fault=3 | 总线超时归类为 SDA_STUCK |
| nack=0 | 本次记录没有 NACK 字节序号，不是已确认的地址 NACK |
| phase=5 | 故障记录在 ADC 寄存器 0x85 读取阶段 |
| b=0x0001000D | 恢复计数 1；总线 FSM 已回 IDLE；FPGA 已释放 SCL/SDA；采样 SCL=1、SDA=0 |
| af=8 | MCU 自动对焦以 I2C_ERROR 停止 |
| p=0 | 软件目标位置寄存器，不能据此认定镜头物理位置已到 0 |

两根线在 FPGA 均释放时 SDA 仍持续为低，是本轮直接观测到的失效状态。尚不能区分镜头从机卡住、连接/电气问题或此前事务时序异常；不能仅凭本记录断定镜头损坏或 FPGA 资源不足。

同期 SPI 接收持续更新：`CNN: 4010` 从 `00001277` 增至 `0000133A`，`4014` 始终为零；B 板 COM16 仍输出 `D` 和 `FRAME_DONE`。

## 根因定位与修正

- 镜头 I2C 仍使用 A 板 R6/R7，SPI 使用 E12/E16/E17/F13，没有直接引脚复用冲突。
- 清晰度统计取 `S_hdmi_base_data`，位于新增 CNN 框和菜单叠加之前；框线本身不会被纳入该统计。
- 本板 BOM 配套手册确认镜头驱动为 DW9714。数据手册规定 I2C 第一个数据字节 bit7 是 PD，置 1 会 power-down；bit6 FLAG 必须保持 0；D[9:0] 是位置 DAC，第二字节低四位是 slew 配置。
- 旧 RTL 将 14 位软件位置原样拆成 `{position[13:6], position[5:0], 2'b00}`。扫描值到 8192 时首数据字节从 `0x00..0x3F` 跨到 `0x80..`，把 DW9714 的 PD 位拉高；位置 >=4096 也会碰到 FLAG 位。
- 这与用户观察到的镜头组件偶发松垂/失去保持力高度吻合，是已确认的固件控制字错误；串口中 SDA 卡低是另一项独立总线故障，不能把它当作唯一根因。
- 已修正位置打包：Byte1=`{2'b00, position[13:8]}`，Byte2=`{position[7:4],4'b0000}`，将 14 位 UI 位置按高 10 位缩放到 DAC，并固定 PD/FLAG 及 slew 字段为零。改动在 `user_source/hdl_source/lens_i2c_ctrl.v`。
- 已扩展 `tests/tb_lens_i2c_diag.v` 覆盖 2228、8192、16383；Icarus RTL test 与 stuck-bus recovery test、MCU autofocus host regression 均通过。RTL 事务中 8192 写 `20 00`，16383 写 `3F F0`，PD/FLAG 两位都保持 0。
- 新 A 板构建脚本为 `tests/build_a_r49_vcm_dac_pack.tcl`。R49 bit 与最终 STA 尚在构建/检查，不可用 R48 代替。

## 现场记录

- 每次位置写入后，镜头控制器继续读取 0x84/0x85；任一事务失败都会锁存 `O_error`，之后普通位置命令被拒绝，必须显式 retry。
- MCU 每次 AF 请求最多执行一次恢复；仍失败则退出至 AF_IDLE，避免无限重试和镜头反复运动。此后不会自行解除错误。
- 本次 SPI 提交没有修改 `lens_i2c_ctrl.v`、`focus_metric.v` 和 `autofocus_control.h`；这不等于已经排除实现时序或电气影响。

## 下一步验证

1. 保持本轮代码不变，给镜头/相机供电断电重上电并重新触发一次对焦；只下载 FPGA 不保证复位镜头从机。
2. 若恢复后再次失效，采集从正常 `s=2 fault=0 b=F` 到首个异常的完整串口过程，记录是 ADC84/85、位置写入还是初始化先失败。
3. 若断电后 SDA 仍为低，先核对 VCM 的 SDA/SCL/GND 连接、供电和上拉；不能靠屏蔽错误使其恢复通信。
4. 若仅当前 A R48 会复现，再在同场景下用 A R47 作对照，B 板保持不变，以区分新增实现影响与原镜头链路问题。
5. 在取得首个异常前，不改清晰度阈值、不取消总线错误保护，也不把 ADC 失败直接忽略为成功。
