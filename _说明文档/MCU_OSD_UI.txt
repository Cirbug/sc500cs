MCU 菜单显示表（MUI1，2026-10-17）

实现范围
主菜单、图像设置、录制设置、模式选择、菜单显示按钮和录制指示灯的
文字内容、数值格式、选中状态、颜色和进度条宽度由 MCU 生成。
FPGA 保留固定网格扫描、通用字符/进度条绘制与视频叠加。
触屏命中区域与原来的 menu_input.h 一致，未改变双击对焦或云台手势。
这不是全屏软件 framebuffer，也不是任意布局的 LVGL 接口。
时钟、HDMI/MIPI 测量、对焦框和图形识别结果标签仍由现有硬件生成；
菜单和识别结果共用原来的同步中文字库，不复制字库。
现有 30 fps 摄像头配置、完整可见区判定、DDR 三帧所有权均未改动。

传输与显示
MCU 只在界面内容变化时写 256 个 32-bit 单元（1 KiB），不传输视频。
512x32 双时钟 RAM 分成两个 bank，像素端只读当前 bank。
写满后提交一个 toggle，经三拍同步后只在 VSYNC 上升沿换 bank。
回执同步到 APB 前，禁止 MCU 修改待显示 bank；驱动直接返回，不忙等。
没有更新或 MCU 暂停时保持最后一张菜单；上电未收到首张有效表时不画菜单。
新增一个像素周期流水线，RGB、DE、HS、VS 一起延迟，不增加一帧缓存。

APB 地址（基地址 0x70002000）
0x00 RO: 0x4D554931，ASCII MUI1；旧 FPGA 不匹配时 MCU 不写显示表。
0x04 RO: bit0 BUSY，bit1 已有有效表，bit2 写入/提交错误。
0x08 WO: 写 0 开始一张新表，清计数与错误（BUSY 时拒绝）。RO 返回写入数量。
0x0C WO: 32-bit 连续写入数据，内部计数递增，最多 256 字。
0x10 WO: 提交；必须完整写满 256 字且没有错误。
需要全字节 strobe；不完整提交、超长、BUSY 时写入都会置错误位。
错误后等待 BUSY 清零，重新从 0x08 写 0，再完整提交。
复位同时清两侧握手、有效位，不复位 RAM；valid=0 防止显示未初始化 RAM。

显示表格式
每行 16 单元：0..7 为左侧标签，8..11 为右侧数值，12..15 保留。
行 0..8 为菜单九行，行 9 为常驻菜单按钮，行 10 为录制指示灯。
其余行写零。每个单元重复该行的属性，避免另设属性 RAM。
bit 23: 可见；22..16: 进度条宽度 0..127；15: 增益进度条底色；
14: 进度条；13..12: 背景 0普通/1选中/2编辑；
11..9: 前景调色板；8: ASCII；7..0: ASCII 编码或中文字模 ID。
0 号中文字模为空格。ASCII 5x7 放大为 20x28，中文使用原有 32x32 字模。
tools/generate_mcu_menu_map.py 从 assets/menu_font/manifest.json 生成 MCU ID 表。
新增字体后先更新原字体生成结果，再运行这个脚本，保持 MCU 与 FPGA ID 一致。

MCU 内存与启动
RAM 调试版本仍为 48 KiB TCM，保留 1 KiB heap 和 2 KiB stack。
为容纳界面生成代码，允许普通代码链接 relaxation；SDK 启动汇编中的
GP/TP/SP 初始化用 .option norelax 保护。不能只改链接参数而漏掉启动汇编。
tests/check_mcu_ui_elf.py 校验最终 ELF 的初始化指令、栈地址与段不重叠。
两个 MCU 工程均接入显示表；它们原本的追踪功能差异没有在本次合并。

交付注意
新 bit 必须配套新 MCU 固件，旧固件不会生成显示表，菜单将不会出现。
新固件可以识别旧 bit 并继续使用旧寄存器菜单，便于回退。
最终资源/时序和可下载产物以 bank/mcu_ui_20261017 下的构建报告为准。
仿真与编译通过不等于板上验证。本流程不会自动烧录 FPGA 或 Flash。
