双板图像处理整合版 — 320×180

PH1P35 主板保留摄像头、1920×1080 HDMI、菜单与 MCU；从干净画面每 6×6 像素采样一次，发送 320×180 RGB332。
EG4D20 从板处理全部 57,600 个像素，没有二次降采样。红色目标与形状识别同时计算，只回传结果；主板按 6 倍映射坐标。

下载
新配套文件：output320/camera_network.bit（主板）、output320/eg_image_sink.bit（从板）。旧 output 是160×90，不可混用。
两板 SRAM 下载后，用 FD 的 anlu_app_camera_net 配置加载 FDwork/anlu_app/build/anlu_app.elf 并运行。
FD 使用 camera_net_ram.cfg，USB位置1-13；BitWriter 与 FD 不应同时占用主板下载线。
SRAM 和 MCU RAM 下载断电失效，本次没有改写启动 Flash。
两板RJ45直连。主板192.168.50.1:6001 MAC02:00:00:00:00:01；从板192.168.50.2:6002 MAC02:00:00:00:00:02。
R10、R11用于主板网口，整合顶层移除旧复位/背光映射。固定直连版没有ARP/ICMP，不能用ping检查。

识别与帧率
完整分辨率八邻域连通区域分析；每帧选最大的合格红色目标与最大的已识别形状。
红色至少128像素、宽高至少6像素，目标距画面边缘至少2像素；形状至少96像素、宽高至少10像素，贴边不作形状识别。
类别0未识别、1矩形/正方形、3圆形、4三角形。采用轮廓行宽与填充比例规则，不是通用物体识别模型。
矩形主要适合水平/垂直边，三角形主要适合上下朝向；任意旋转、遮挡、低对比和复杂纹理仍可能失败。
RGB332为8位量化颜色，亮度、白平衡和背景会影响识别。
红色需满足更强的通道优势和饱和度、填充比例至少25%，连续三帧位置相近且面积变化不超过两倍才确认。丢失或突然跳到远处立即取消有效状态，不输出移动命令。超过0.5秒没有完整分析帧则重新确认。
主板形状显示容忍两次短暂漏检，第三次撤销；红色方向命令只采用当前有效结果。
15个HDMI帧没有新结果时撤销有效状态（HDMI30Hz时约0.5秒）。
取消旧版每帧后固定等待一秒；实际帧率受采集、逐包确认及场景分析时间影响，以实测记录为准。
网络125MHz、分析25MHz；4KiB环形采集缓存保留未确认数据，缓存超限丢弃整帧。
不完整帧不进入识别；丢包最多重试两次；分析队列超限或处理超时报告失败，不返回半帧目标。
网口不会阻塞本地HDMI。

协议（大端）
每帧57,600字节，240包，每包UDP负载256字节：16字节头+240像素。
请求：PHIM(4)、帧号(4)、包号0..239(2)、总包数240(2)、像素长度240(2)、格式2(1)、类型1(1)。
无图像时心跳只有16字节头，包号/总数/长度/类型为0，格式仍为2。
回复48字节：0..3 PACK；4..14对应请求；15状态(0成功1乱序)；16..19完整帧数；20..23错误数。
24标志(bit0红色有效、bit1形状有效、bit7处理失败)；25形状类别。
26..27红色中心X；28..29中心Y；30..31红色X0；32..33Y0；34..35X1；36..37Y1。
38..39形状X0；40..41Y0；42..43X1；44..45Y1；46红色面积百分比；47形状面积百分比。
坐标均16位，基于320×180。末包确认等待本帧处理完成；主板只在该确认后采用结果。
重复末包只重发结果，不重复累计帧数。协议栈检查MAC FCS和IP头校验。

诊断地址
基址0x70000000，偏移4000 NET1；4004发包；4008确认；400C确认帧；4010超时/丢帧；4014坏确认；4018从板帧；401C从板错误。
4020状态；4024宽高014000B4；4028高16位标志/类别；402C红色X0/Y0；4030形状X0/Y0。
4034高16位两个面积百分比、低16位宽320；4038红色中心X/Y；403C红色X1/Y1；4040形状X1/Y1。
坐标寄存器高16位X、低16位Y。

构建
python board_link/camera_net/prepare.py
TD分别执行build_main320.tcl、build_eg320.tcl。
python board_link/camera_net/tests/run320.py
python board_link/camera_net/finalize320.py
产物位于桌面bank/camera_net_20261019的fpga_320、eg_320、sim320；发布到output320。
发布要求两板时序和320回归全通过；包含校验和、源码快照与MCU固件副本。
原始主工程顶层保持不变；整合副本由prepare.py生成，功能修改应保存到rtl和生成脚本。

实机
确认摄像头画面后进入红色跟踪或形状识别，用背景干净、光照均匀、轮廓完整的目标。
依次展示红物体、圆、矩形、三角形，各保持两秒，同步检查回传有效位、坐标和屏幕框。
移走目标应撤销结果；断网应撤销过期结果，本地HDMI继续显示。
编译和仿真不等于实物准确率验证，现场结果单独记在output320/hardware_validation.json。
